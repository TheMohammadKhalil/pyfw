# 4 · Bridge and router modes

## Bridge mode

Both laptops belong to `192.168.10.0/24` and use the E3200 at `192.168.10.1` as their gateway. Traffic between the laptops stays within the local network.

The mini PC has no IP address on its two Ethernet ports. It receives each frame, applies the rules, and sends accepted frames through the opposite port. Source and destination addresses stay unchanged.

The implementation is in [mini_bridge.py](../code/mini_bridge.py).

## Router mode

The mini PC connects two separate networks:

```text
192.168.10.0/24 ── p25: 192.168.10.10 [ pyfw ] p1: 192.168.2.1 ── 192.168.2.0/24
```

Laptop B uses the mini PC as its gateway. The E3200 needs a static route to Laptop B's network through `192.168.10.10`.

Linux performs the routing. The rules generated by [router_nft.py](../code/router_nft.py) filter forwarded traffic with nftables. Forwarding is restricted to the two selected Ethernet interfaces. The input chain permits ICMP and established or related traffic from those interfaces, then drops other traffic addressed to the mini PC through them.

The setup uses routing without NAT. Existing host firewall rules can also affect traffic.

## Comparison

| Mode | Bridge | Router |
|---|---|---|
| Networks | One shared subnet | Two separate subnets |
| Mini PC Ethernet addresses | None | One per port |
| Forwarding | Python raw sockets | Linux IP stack |
| Filtering | Python rule engine | nftables |
| Laptop B gateway | E3200 | Mini PC |

See [setup](03-setup.md) for the commands for each mode.
